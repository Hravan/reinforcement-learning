Notes:

- ActionSelectionMethod, StepSizeMethod and ValueEstimationMethod are
  duck-typed protocols, not real Python base classes: any object with the
  shown shape qualifies.
- Agent holds action_selection_method and value_estimation_method as plain
  attributes and calls them as self.action_selection_method(context) /
  self.value_estimation_method.update(self, action_index, reward) from
  act(). action_selection_method never receives the Agent itself, only its
  ActionSelectionContext.
- Agent builds _action_selection_context once, in __init__, and reuses the
  same instance for every act() call: it holds n_actions (fixed for the
  agent's lifetime), a reference to the same Experience instance Agent uses
  (n_selected(action_index) and len() are O(1), so nothing needs
  precomputing), and a reference to reward_estimates (None if the agent has
  no value_estimation_method). Both experience and reward_estimates are
  mutated in place elsewhere, so the same context instance always reflects
  current state without being rebuilt. It has no reference back to Agent
  itself, so action-selection strategies stay decoupled from Agent's other
  internals (action_selection_method, value_estimation_method, the actual
  Action objects and their true values).
- value_estimation_method is optional: None means the agent keeps no
  per-action reward estimates. GradientBandit is the example: its action
  preferences have no interpretation as action values (per the book), so a
  GradientBandit-driven agent has no use for a ValueEstimationMethod at
  all. EpsilonGreedy and UCB, by contrast, read Agent.reward_estimates and
  so require one.
- Agent.reward_estimates is a read-only property delegating to
  value_estimation_method.estimates.
- IncrementalValueEstimation updates its estimates using a StepSizeMethod,
  defaulting to SampleAverageStepSize (1 / n times this action was chosen).
- EpsilonGreedyAgent is a thin Agent subclass that wires up EpsilonGreedy
  as the action-selection strategy.
- Action.perform() only samples a reward. Action.drift() applies one
  random-walk step to the true value (a no-op if stationary). Agent.act()
  calls perform() on the chosen action and drift() on every action, so all
  actions drift each step regardless of which was chosen.
